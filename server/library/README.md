# Library — 基础纸样库

The base pattern library: the validated formulas this project's engine
drafts from. Every design here is vendored FreeSewing source (MIT --
see `NOTICE.md`), with only the intra-library imports rewritten to
relative paths. The framework (`@freesewing/core`, plugins) is NOT
vendored; it stays a pinned dependency in `server/package.json`.

## Layout

```
library/
├── README.md, NOTICE.md
├── blocks/
│   └── brian/              # base block: menswear body block (the foundation)
├── designs/
│   └── teagan/             # garment: fitted knit tee, built on Brian
├── parts/
│   └── library/            # reusable parts (sleeve, rectangle, two-part-sleeve, ...)
└── data/                   # 款式数据
    ├── models.json         # standard measurement sets (40 sets)
    └── schemas/            # per-design requirements (from getConfig)
        ├── brian.json, teagan.json, library.json
```

Categories are organisation only -- the runner scans every
`<category>/<name>/src/index.mjs` and treats a directory as a design
when its module exports a design constructor named after the
directory. Adding a category needs no code change.

## What is in each design

A design is a directory with the same shape FreeSewing uses:

```
<name>/
├── src/
│   ├── index.mjs    # Design definition: parts list + i18n merge + exports
│   ├── front.mjs / back.mjs / sleeve.mjs / base.mjs ...
│   │                # the formulas: one file per part, each a draft()
│   │                # function that computes points, paths, notches
│   │                # from measurements + options
│   └── shared.mjs  # helpers shared by the parts
├── about.json       # id, name, description, difficulty, tags, version
├── i18n/            # display strings (en.json + index.mjs)
├── package.json     # provenance: original package name + version
└── README.md        # the design's own documentation
```

The formulas are the draft functions. A part's `draft()` reads
`measurements` (the person) and `options` (the garment: ease, fit,
style) and computes geometry with the core's point/path/curve tools.
Nothing is a lookup table: the numbers come out of the code.

## The three designs

| Design | Kind | What it is | Needs |
|---|---|---|---|
| `brian` | block | Menswear body block: front/back + sleeve, the base every top is built on. 11 measurements. | `@freesewing/library` (sleeve), `@freesewing/plugin-bust` |
| `teagan` | garment | Fitted knit tee on the Brian block. 13 measurements. | Brian (`base` part + i18n), library sleeve |
| `library` | parts | Reusable parts: sleeve, rectangle, two-part-sleeve, three-part-hood. Drafts parts, not a garment. | core only |

Dependency chain: `teagan → brian → library → core`. Teagan's
`front.mjs` imports Brian's `base` part; both Brian and Teagan use the
library sleeve. Those imports are relative inside this library now
(see the header comment on each rewritten file); only the framework
imports (`@freesewing/core`, `@freesewing/plugin-bust`) still resolve
from `server/node_modules`.

## Data (`data/`)

- `models.json` -- 40 standard measurement sets from
  `@freesewing/models` (neckstimate: every set is generated from a
  neck circumference; groups adult/doll/giant). Reference bodies for
  testing a draft -- never a substitute for the user's own
  measurements.
- `schemas/<design>.json` -- what each design needs: required +
  optional measurements, and every option with its default and
  min/max. Generated from the designs themselves (`getConfig()`), same
  source the `freesewing_design_info` tool reads.

Both are regenerated by `../engine/data/generate.mjs`. Do not hand-edit.

## Add a design

Copy the design's `src/`, `about.json`, `i18n/`, `package.json`,
`README.md` into `library/<category>/<name>/`, rewrite any
`@freesewing/<other-design>` imports to relative paths inside the
library (leave `@freesewing/core` and `@freesewing/plugin-*` alone),
then run `node ../engine/data/generate.mjs`. The runner picks it up
with no code change. (Design tests are not vendored -- they depend on
the FreeSewing monorepo's shared test harness; this project's
verification is the draft comparison in the MCP test suite.)

## Our own designs go here too

A house block or a made-to-measure formula is a design in the same
shape: a directory under `library/<category>/<name>/` with `src/`,
`about.json`, `i18n/`. It can import the core and the library parts
the same way Brian and Teagan do, and the runner drafts it like any
other design. That is the point of having the library in this repo
instead of in `node_modules`.
